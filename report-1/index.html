The findings

Every setup is compared with Claude Code on Sonnet 5.5, except the last chart, which compares a fresh session with continuing the session. The square shows the result overall with its 95% interval, and each dot is one repo. Left of the dashed line means lower (cheaper or fewer tokens), right means higher.

A result counts as a finding only if it was pre-registered as the comparison's primary measure, its Holm-adjusted p is below 0.05, and its direction holds in at least 5 of the 6+ repos. Everything else is reported as "not shown", with its interval.

How it was done

  • Repos, picked by a rule written before any run: litestar, starlette, click, pyinfra, axios, lint-staged, recharts, homebridge. pydantic was replaced by the first reserve, litestar, under that rule, because it now builds its core from Rust source.
  • Commits: the first 7 per repo after every model's training cutoff (2026-07-01) whose tests fail before the change and pass after it, twice each. Every candidate checked is listed, with its fingerprint.
  • Task: the commit message plus the names the hidden tests import. The commit's own tests decide, and any edits an agent makes to them are undone first.
  • Sandbox: each run starts from a fresh copy without git history. The only network is the model's API.
  • Setups: Claude Code 2.1.287 on Sonnet 5.5, Haiku 5.5 or Opus 5.5; Codex 0.159.2 on gpt-6.1-sol; RTK 0.51.0 on Sonnet 5.5. Fresh-session pairs: task 1 in a session, then task 2 either continued or started fresh with a one-line summary.
  • Statistics: 5 primary comparisons, Holm-corrected, with a headline only if the direction holds in at least 5 of the 6+ repos. The pre-registration is frozen on GitHub.

What went wrong, and what we changed

  • Before any paid run, the harness was fixed so tests run fairly. Without these fixes, agents would have been marked as failing in 4 repos:
    • localhost networking for tests' own servers;
    • placeholder versions for builds that read git history;
    • coverage thresholds off;
    • imports from a folder;
    • dependencies pinned to GitHub commits.
  • The $1.95 pilot found that Claude Code shows Haiku 5.5 runs at about 27× the published price. Every run is priced from its tokens at the published prices.
  • During the run, both accounts ran out of credit once. Interrupted runs were redone. Codex's quota error was at first misread as aimpg's own failure, which wrongly excluded 2 commits; that was repaired before the analysis. The original file is published.

All of these are dated in the pre-registration's change and deviation lists.

Check it yourself

  • Raw data: every run record (outcome, tokens per request, cost and time), the selection lists and the analysis output.
  • Rerun any comparison on your machine: aimpg verify --rerun <record> --repo <clone>. Independent reruns appear as Reproduced on the scoreboard.
  • Code: aimpg (MIT), with aimpg/replay/study.py for the statistics.

Limits

  • This covers 8 Python and TypeScript repos with good test suites, and tasks small enough to judge by tests. It may not hold for large refactors or other languages.
  • One configuration per tool, at default settings. RTK's maintainers were asked to review their setup and didn't reply by the deadline (discussion).
  • Prices change. The ratios hold only as long as the published prices behind them do.
  • aimpg is built by one developer using Claude Code. The author paid for every run and has no affiliation with any vendor tested.
